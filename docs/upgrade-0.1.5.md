# 升级到 0.1.5

先备份专用 MySQL 库和客户端 SQLite（停止客户端后包含 WAL/SHM），更新代码，运行 `bun install --frozen-lockfile`，重启服务和 MCP。首次离线启动与缓存路径兼容性见 [0.1.4 升级说明](upgrade-0.1.4.md)。

服务端启动幂等补建 mb_operations_memory(namespace,project,memory_id)。已有部署如果撤销了 INDEX，升级前重新授予，确认创建成功后可撤销。原记录和回执保留；旧程序可忽略新增索引，回滚时无需删除。生成列迁移仍遵循 0.1.3 的 ALTER 要求。

空查询快照在 TTL 内保持新鲜，详情读取不清项目查询快照；本地写入、删除、冲突处理仍使相关查询失效，refresh=true 可主动刷新。批量缓存写入后只淘汰一次，pending 记忆不淘汰。查询快照代表某次查询结果，不能被当作实时视图。

服务端在 SQL WHERE 中过滤过期记忆，再应用 LIMIT。比较毫秒时间，处理 Z、正负时区偏移和任意小数秒精度（与 Date.parse 一样截断到毫秒），不依赖 MySQL 会话时区；未设置及 null 表示不过期。recent 和 timeline 只向应用传回索引字段，body/sources 仍由 get 返回。数据库仍需解析 JSON，子串 search 保留标题/正文校验及分页，没有新增全文索引。

同步一批最多 50 项、4 个独立请求并发，同一记忆 ID 不并发；SQLite 回执写回在同步事务中串行完成。临时失败停止派发新操作，已经发出的请求仍可完成，后台退避 5 秒；显式 sync 可立即重试。冲突保留，幂等操作 ID 不变。

remember/forget/确认 rebase 在权限检查后只等待后台同步最多 2 秒，MCP sync 同样最多等 2 秒。首次身份验证仍可能额外等待 10 秒。返回 pending 代表已持久化但尚未确认上传，后台可稍后同步；查询 status 确认，不要重复创建操作。关闭客户端会中止其网络请求、保留未确认队列，服务端已提交但本地未收到确认的操作下次按原 ID 幂等重放。

鉴权配置摘要在 handler 创建时预计算，每请求只计算一次 Bearer 摘要并做 timingSafeEqual。令牌调整后仍需重启服务；未新增令牌热更新。

doctor 仍兼容 0.1.3+ 服务端；使用 SQL 查询性能改进需要升级服务端。数据生命周期、全文检索与人工确认弹窗仍未实现。
