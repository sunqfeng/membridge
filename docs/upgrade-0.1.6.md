# 升级到 0.1.6

更新代码、运行 `bun install --frozen-lockfile` 并重启 MCP。服务端 API、数据库与缓存结构不变；原有迁移和备份要求见 [0.1.5](upgrade-0.1.5.md)。回滚客户端无需数据降级，但会恢复首次身份验证额外等待 10 秒的行为。

remember/forget 使用同一个基于 performance.now 的 2 秒前台网络等待截止时间，覆盖身份验证与后续同步，不会每阶段各等 2 秒。后台身份请求继续使用 10 秒网络超时和单飞机制；前台超时不会取消它。未知权限的内容可暂存为 access=unknown、pending，只有验证 namespace/agent 和 rw 后才能上传。已知 ro 在请求网络前立即拒绝；后台新发现 ro 会保留本地内容并标记 blocked，修正凭据或明确丢弃后才能处理。

这个预算约束网络等待，不会中断必须完成的本地 SQLite 持久化。MCP 初始化的身份发现仍有 10 秒上限，确认 rebase 的预览流程仍要求联网，这轮没有改变它们。

URL 脱敏排除密码中的未编码 /，以保留带端口的 @ 路径。密码中的斜杠需编码为 %2F；未编码斜杠的异常连接串不保证被该规则识别，详见 [上游与脱敏边界](upstream.md)。

expires_at_ms 独立整数列留待单独数据库迁移。本轮保留 expirySql，因此 MySQL 仍有 JSON/日期字符串解析成本；现有 SQLite 和真实 MySQL 集成测试继续验证时区和小数秒边界，没有把性能优化当作已完成。

迁移需同时覆盖：旧记录按 Date.parse 回填；新服务同事务写 payload 与整数列；旧服务只改 payload 时仍更新整数值（可评估存储生成列或迁移期间写入隔离）；删除清除到期值；迁移幂等重试与回滚。索引还需按实际查询评估：到期范围和 updated_at 排序未必能由同一索引同时满足。完成兼容性验证后再移除 expirySql 回退路径。
