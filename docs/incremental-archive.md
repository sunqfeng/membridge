# 增量聊天归档

增量归档是用户明确启用的独立采集任务。它读取已落盘的可见聊天和工具记录，与上次采集的条目哈希比较，再通过持久化队列交付云端。它不需要 agent 主动调用 `remember`，也不调用付费模型。

当前仓库提供 `src/archive.ts` 的队列和交付校验核心。原生日志格式解析、私有路径、凭据读取及操作系统任务由部署侧适配器负责；克隆仓库或安装 MCP **不会默认开启聊天采集**。现有 MCP 工具及服务接口保持兼容。

## 数据与查询

- `codex-history` 保存脱敏后的正文。历史基线不重新导入；新增条目追加，修改过的条目保存修订，标明被替代的 `item_id`。
- `codex-history-index` 保存可更新的会话目录。先搜索会话标题或项目关键词，再读取最新的“自动归档目录”，按 ID 顺序取基线与增量正文。相同 `item_id` 以最后一条修订为准。
- `codex-knowledge` 保存原生长期资料的增量变化。

目录每页最多列出 180 个正文 ID；入口页列出其他目录页。正文按 UTF-16 安全边界拆分，不拆开代理对。历史内容仍是 `untrusted_evidence`，不替代新会话的指令或未经验证的当前项目状态。

## 持久化与交付

`ArchiveQueue` 的 SQLite 状态独立于 MCP 缓存，包含条目哈希、目录版本和待传批次。采集结果与进度在同一事务提交；每个交付批次最多 100 条操作。断网、退出或部分上传不清空队列。

服务端 `applyArchiveBatch` 复用 `MemoryStore.put` 的授权、版本检查和幂等事务，逐条回读正文、标题、来源、作者与版本。只有批次 ID、内容 SHA256 和回读条数匹配，客户端才确认本地批次。严格按队列顺序交付，目录版本包含已排队操作，不因离线积压误覆盖。其他写入者修改归档记录后会停止交付并保留待处理内容。

部署侧通过 SSH 运行受限归档任务，限制可写集合为上述三个集合，并使用真实 agent 项目授权。无需修改云服务的 HTTP 限流或开放公网数据库。

## 当前 Windows 部署约定

经用户明确开启的本地适配器使用 Windows 任务计划，每 5 分钟运行一次，登录时补传，运行窗口隐藏。退出 Codex 后仍可处理已经落盘的记录；关机、休眠和注销期间不能运行，下次登录或唤醒后补传。

只采集用户可见的消息和可见工作记录。内部推理、系统/开发者上下文、内部自动审查会话和秘密均排除；图片、音频保留引用，不上传二进制附件。不同客户端的原生日志需要各自适配器，其他 agent 可以通过现有 MemBridge 权限读取归档。

采集输出和队列目录仅当前用户与系统可访问。适配器对未变化的文件和投影表使用元数据指纹，避免每轮重读全部历史正文。部署保留状态文件、最近运行结果、离线续传验证及关闭入口。队列达到配置上限时暂停新增采集，保留源日志并继续尝试交付。

## 验证

```sh
bun test tests/archive.test.ts
bun run typecheck
```

回归覆盖基线去重、真实 `final_answer` 阶段、持久化重启、确认哈希、修订保留、Unicode 分片、拒绝内部条目、部分上传重放、人工编辑冲突及只读身份。部署另需验证真实云端回读与实际操作系统任务，不能用核心单元测试替代。
